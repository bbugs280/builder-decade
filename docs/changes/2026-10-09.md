# 2026-10-09 — Fix: solo-calc `scope` selects clipped their option text

## Summary
Vincent reported (with a screenshot) that the three dropdowns in the
`trust-scope-reversibility` calculator rendered as truncated stubs —
reading "One c" / "My ow" / "Mone" instead of the full option labels.
Fixed in `assets/css/extended/custom.css`. No content change, no shortcode
PHP/HTML change — **CSS only**.

## Root cause — a two-link circular sizing chain
The `scope` mode is the only mode that uses `<select>` instead of
`<input type="number">`. A select cannot shrink below its widest option, so
it exposes a `%`-based `max-width` that number inputs happen to hide.

1. **`.sc-in { max-width: 45% }` resolved against `.sc-fieldwrap`, not the
   card.** `.sc-fieldwrap` is `flex: 0 0 auto`, and its width comes *from* the
   select's own `width: 9rem` (144px). So `45% × 144px = 64.8px`.
   Measured: all three selects rendered at **65px**; the longest option needed
   306–388px. → clipped.
2. **After fixing (1), the label starved the select.** The label is
   `flex: 1 1 60%` — on a 668px row it grabbed 660px, leaving the select
   ~21px short. Selects rendered 365 / 353 / 336px against needs of 386 / 374 / 307.
3. **The fieldwrap still hugged the select.** With `flex: 0 0 auto`, the
   wrapper's width equalled the select's content width — so the select's own
   `max-width: 100%` resolved against a hug of itself. Circular again; the
   select could never exceed itself + the arrow gutter.

## The fix (three linked rules, all in `custom.css`)
```
.sc-in                          max-width: 45% → 100%   (base, all modes)
scope rows  .sc-row > span:first-child   flex: 1 1 60% → 0 1 auto   (label yields)
scope rows  .sc-fieldwrap                flex: 0 0 auto → 1 1 auto   (wrapper grows)
scope selects  [data-k=reversible|blast|stakes]
                width: 100%; min-width: 0; text-align: left; padding-right: 2rem
mobile ≤600px   same three selects: width 100%, min-width 0, max-width 100%
```
Also `text-align: right` → `left` and `font-variant-numeric: normal` for the
selects — a dropdown's selected option should read left-aligned, and the values
come from a fixed list, not a numeric column.

Scoped via `:has(.sc-in[data-k="reversible"])` so **hire / price / build are
untouched** — verified: those modes contain zero `<select>` and none of the
three scope `data-k` keys.
