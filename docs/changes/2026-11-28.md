# 2026-11-28 — Migrate builderdecade.com from GitHub Pages to Cloudflare Pages

**Card:** `E4H8CDJL` (absorbed `xOoTEMRy`) — "Migrate builderdecade.com to Cloudflare Pages"

## Why

GitHub Pages has **no request logs, no `_redirects`, no `_headers`, no cache-control**.
Structural ceiling, not a setting. The AI-crawler logging motivation was already
measured as weak on traindecade (it says *that* you were crawled, not *why* a page
got cited) — this migration is for the infra reasons, with logging as a free bonus.

## What changed

| Surface | Before | After |
|---|---|---|
| Deploy workflow | `Deploy Hugo site to Pages` → `actions/deploy-pages@v4` | `Deploy to Cloudflare Pages` → `cloudflare/wrangler-action@v3` |
| Build + 4 gates | unchanged | unchanged |
| Live host | `server: GitHub.com`, `via: 1.1 varnish` | `server: cloudflare` + `cf-ray` |
| Crawler logging | none, ever | `functions/_middleware.js` → D1 `ai_crawler_log.ai_fetches` |

**The old GitHub Pages workflow was DELETED in the same change**, not disabled.
Leaving both means a future session sees a green Pages run and concludes it
deployed while the site actually serves from Cloudflare.

## The three traps carried over from traindecade — all avoided

1. `functions/_middleware.js` at repo root, **never** `static/_worker.js`.
   Deploy log said **`Uploading Functions bundle`** — the working path.
2. `await next()`, not `env.ASSETS.fetch(request)`.
3. `waitUntil` destructured from `context` — there is no `ctx`.

## D1 binding — the step with no file-based config

A Pages project **ignores** `[[d1_databases]]` in `wrangler.toml`. The binding was
set per-project via the API on **both** production and preview:

```
PATCH /accounts/<acct>/pages/projects/builderdecade
  deployment_configs.production.d1_databases.DB = 31d1fc93-d6ec-4234-820b-892ad77d656c
  deployment_configs.preview.d1_databases.DB    = (same)
```

`ai_crawler_log` is **shared with traindecade** — `ai_fetches` carries a `host`
column, so one database serves both sites and rows stay separable.

## ⚠️ The build-time diagnosis on the card was WRONG

The card said creating the Pages project needs a GitHub OAuth grant the wrangler
token lacks. **Measured otherwise:** `wrangler whoami` showed `pages (write)` was
present; the first create failed with **HTTP 500 Internal Server Error** — a
transient Cloudflare fault. A retry succeeded immediately.

Lesson: a 500 is not a 403. Reading the log's actual error code before minting a
new credential saved a pointless permission dance.
