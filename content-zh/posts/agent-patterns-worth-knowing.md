# 三個值得認識的 Agent 模式（先別怪模型）

第一次 agent 搞砸時，你的本能是換更大的模型；第二次，是「把 prompt 寫得更用力」。兩者都錯過了重點。

一個出錯的 agent，通常不是笨模型，而是你給了它一個錯誤的「工作形狀」。你選擇的模式——模型如何路由、它能碰哪些工具、它會不會檢查自己的成果——決定了它看起來聰明，還是一再以同樣可預測的方式失敗。

有三個模式值得你記住名字，不是因為它流行，而是因為**每個模式的存在，都是為了解決某種特定的失敗模式**。搞清楚你在對抗哪種失敗，模式就自己會挑好。

## 模式一：路由（Routing）——當輸入開始長得不像彼此

問題是這樣的：一個 prompt 是退款申請，下一個是帳單 bug 回報，再下一個是「你們的退款政策是什麼？」。用單一 agent 同時處理這三種，它會信心滿滿地用同一套泛泛而論的方式硬闖過去，因為它沒有任何理由區分對待。

**路由**透過在行動之前先做一個決策來修正這點：先分類輸入，再把它送給對的專家。那個專家可以是不同的 prompt、不同的模型，或不同的程式路徑——重點是**分離**，不是機制。

路由要解決的失敗模式是**異質性**。一個 agent 處理多種輸入時，會漂向「平均」。路由的意思是：平均的答案是對每個具體案例都錯的，所以別再平均了。

你需要它的徵兆很簡單——當你發現自己在單一 prompt 裡寫「如果使用者問的是 X，那就……」，你就是在用散文手刻一個路由器。把它抽出來，做成真正的決策。

## 模式二：工具使用（Tool use）——當模型一直自己編造答案

問模型「我現在的餘額是多少」，它會信心滿滿地報出一個它編的數字。這不是偷懶；模型只知道自己訓練時見過的東西，而你的餘額不在裡面。

**工具使用**是把 agent 從「知識」系統變成「行動」系統的模式。給它一個函式——`get_balance()`、`search_docs()`、`run_query()`——它就不再憑空捏造答案，而是去**抓取**答案。

工具使用要解決的失敗模式是**在資料缺失時的胡編**。當 agent 不知道、又沒有方法去查時，它會用自信的虛構填補空白。工具就是從虛構逃回事實的出口。

微妙的反向陷阱是：**工具爆炸**。加太多工具，每個決策都會變難，而不是變簡單——模型現在得在三十個選項裡挑對的才能行動。對獨立開發者來說，紀律是讓工具面保持小而精準地命名。三個描述清楚的工具，永遠勝過三十個含糊其辭的工具。

## 模式三：反思（Reflection）——當工作細緻、「錯得不明顯」又很便宜時

有些輸出明顯對或錯。但多數有趣的工作不是這樣。一段生成的函式通過了 lint，卻仍然有微妙的錯誤；一篇文章讀起來順暢，卻什麼都沒說。

**反思**加上第二次的檢視：先生成，再**針對某個標準批判**，然後修正。agent 在你看見之前，先檢查自己的成果。

反思要解決的失敗模式是**沉默的錯誤**——那些「不會報錯的錯誤」。它是三者中唯一會真正增加**成本與延遲**的（多一次模型呼叫，有時是一整串），所以是你設門檻最嚴的一個。反思只有在以下情況才值得付出代價：

- 正確性真的很重要（錯的答案昂貴——錢、資料、信任）。
- 你能清楚說出標準（「這樣能編譯過嗎？有沒有處理空值的情況？」）。
- 你寧可燒 token，也不願花自己的review時間。

對於一個快速的查詢或發散式腦力激盪，反思純屬浪費。但對於會碰到使用者資料的那段程式，它是你能買到最便宜的保險。

## 真正的技能是診斷失敗，而不是選模式

對獨立開發者來說，這才是關鍵的重構——因為當它壞掉時，**你是唯一會去 debug 的人**：

**別先抓模式，先抓失敗。**

- Agent 對各式各樣的問題都給出含糊、攪在一起的答案 → **路由。**
- Agent 憑空捏造事實或數字 → **工具使用。**
- Agent 的答案看起來對，但經不起推敲 → **反思。**

你每加一個模式，就買到一項能力，也**多付一種新的失敗方式**——更多延遲、更多 token、多一個要自己扛的活動零件。獨立開發者的紀律不是三種全疊上去，而是加上**能殺掉你實際看到的那個失敗、最小的一個**模式，其餘的都別加。

更大的模型修不好路由問題；更好的 prompt 修不好缺失的工具。模式才是藥，不是模型——而知道你需要三者中的哪一個，正是「它為什麼一直這樣」與「好了，修好了」之間的差別。

## 資料來源

- **Zheng et al., *Where LLM Agents Fail and How They Can Learn From Failures*（arXiv:2509.25370，2025）。** —— AgentErrorTaxonomy：agent 的失敗模組化地橫跨記憶、反思、規劃、行動與系統層操作；單一根本原因錯誤會一路串聯影響後續決策。支撐「診斷失敗，而非選模式」的論點。
- **Ng, *Agentic Design Patterns*（DeepLearning.AI，2025）。** —— 反思適合用在「品質比速度重要、且有清楚正確性標準可系統性評估」的任務；它帶來的成本與延遲，不值得花在簡單查詢上。
- **OpenAI, *Agent Design Patterns* 指南（2025）。** —— 路由、工具使用、反思的經典框架；路由是行動前的決策，工具使用讓 agent 能行動，反思是自我批判。
- **LangChain / RAGyfied, *Agentic Design Patterns*（2025）。** —— 「工具爆炸」問題：工具越多，agent 的決策越難；應分組工具、採用階層式選擇、並設定呼叫預算。
